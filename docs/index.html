Why this exists

把“灵光一现”变成
可复用的产能。

一篇好文章可以靠灵感。一个每天更新的系列，只能靠流程。这个 skill 关注的是灵感之后的那部分。

01 / EVIDENCE

先抓证据

每个主题先生成 research.md，原始段落留在磁盘上。写作从材料出发，而不是从模型的记忆出发。

02 / JUDGMENT

编辑门禁

字数、正文、章节、开头、确定性说明和术语表由脚本检查。结构问题在发布前暴露。

03 / STATE

库存有状态

article.md、.sent 和 meta.json 共同定义稿件的生命周期。断网、重启或换终端都能恢复。

04 / DELIVERY

写发分离

写作只补库存，投递按 queued_at 取稿。先备货，再发货，不再到点才发现没有东西可发。

The pipeline

一条线，四个检查点。

每一步都能独立重跑，每一步都留下可检查的文件。

01 / RESEARCH抓证据

保存来源、提取争议点、记录抓取失败，不用记忆填空。

02 / WRITE按规范写

场景、机制、转折、代价、争议，最后是三级确定性说明。

03 / CHECK过门禁

validator 检查结构，作者继续核对事实；通过后才打包。

04 / DELIVER排进队列

以 queued_at 排序，投递成功才写 .sent，失败不跳稿。

Quick start

30 秒把流程跑起来。

这是一个 Codex skill，也是一套可以单独执行的工具包。研究、校验和成品构建只依赖 Python 标准库；PDF 使用本地 Chrome、Edge 或 Chromium。

  • 克隆到 Codex skills 目录
  • 用脚手架建立第一篇稿件
  • 抓取 research.md 后开始写作
  • 通过 validator，再生成 EPUB 和 PDF
install
git clone https://github.com/ironsnake-change/tongshi-series.git "$env:CODEX_HOME/skills/tongshi-series"
first issue
python scripts/new_article.py --root . --id sample-topic --domain "未知与边界" --title "一个具体的标题"
python scripts/research.py "Tunguska event" "通古斯大爆炸" --out 2026-11-05-sample-topic/research.md
quality gate
python scripts/validate_article.py 2026-11-05-sample-topic/article.md
Who it is for

适合长期主义，
不适合内容灌水。

它不会替你决定什么值得写，也不会把没有证据的说法包装成事实。

适合邮件通讯、知识专栏、读书会材料、内部知识库，以及任何需要“主题轮转 + 质量稳定 + 定时交付”的系列。
不适合一次性文章、没有编辑标准的内容农场、希望完全无人审核地自动发布，或者把模型输出当成历史定论。
已验证官方 skill 结构校验、三篇生产稿的质量门禁、脚手架、库存、EPUB 和 PDF 烟雾测试。
已知边界默认来源是 Wikipedia；事实核查仍需人工。公开包不附带邮件凭据和定时投递实现。
